# v0.1.1 发布说明

[项目首页](../../README.md) · [使用指南](../usage.md) · [开发指南](../development.md) · [English](v0.1.1.en.md)

正式维护版本。修复 Windows 登录启动任务安装失败及中文错误乱码，新增立即启动已安装任务的命令。

## 相比 v0.1.0 的改进

- 修复 `jc s startup install` 报“任务 XML 格式不正确 / 无法切换编码”的问题，任务文件改为声明与实际编码一致、带 BOM 的 UTF-16LE，支持中文及其他 Unicode 路径。
- 按 Windows 代码页解码任务计划程序的错误输出，保留底层失败原因，避免中文乱码。
- 新增 `jc server start`（简写 `jc s start`），立即运行当前用户已安装的登录启动任务，复用安装时保存的程序路径、语言和监听配置。
- 启动命令会等待最多 10 秒确认服务控制接口就绪；任务未安装、调度器拒绝启动或服务未就绪时明确报错。任务已运行时重复执行会提示已运行；已有普通后台服务时提示先运行 `jc s stop`。
- 手动启动请求、服务就绪和启动失败写入已有的 `server.log`，不记录配对密钥。
- 补充命令参数、就绪等待、启动超时、重复启动与后台模式冲突的测试，以及双语管理指南。

## 安装与升级

提供 Windows amd64 ZIP、Linux amd64 tar.gz、`release.json` 和 `SHA256SUMS`。压缩包包含程序、双语指南和此发布说明。安装及校验方法见[项目首页](../../README.md#安装)。

从 v0.1.0 升级可保留配对配置和已安装的登录启动任务，无需重新配对。如服务正在运行，先执行 `jc s stop`，再将 `jc.exe` 替换到原路径。已有任务时可直接运行：

```powershell
jc s start
jc s status
```

如果此前因编码问题没有安装成功，先运行 `jc s startup install --listen auto`，再执行上述命令。安装时也可保存明确的监听地址。`jc s start` 不接受 `--listen` 或 `-d`；需要修改任务配置时，先卸载任务，再用所需参数重新安装。

`jc s stop` 正常停止当前服务并保留下次登录自动启动；`jc s startup uninstall` 移除任务并停止任务启动的服务。

## 验证范围与已知限制

- 发布流程执行 Windows/Linux 格式检查、`go vet`、测试和构建，Linux 额外执行竞态检查，并验证发布包校验和及 Linux 命令。
- Windows 测试通过真实任务计划程序校验生成的 XML，但不创建或运行任务。启动流程测试使用可控的调度器替身和本机控制接口；自动验证不覆盖完整计划任务启停、用户登录或实际 VS Code 桌面交互。
- 启动等待超时不会撤销已提交的调度请求；任务后续仍可能启动或重试，请通过 `jc s status`、`jc s startup status` 和日志确认状态。
- 服务端只支持 Windows，客户端只支持 Linux；尚无公网中转和 IPv6 支持。
- 配对配置尚无跨进程锁，请顺序执行创建和撤销操作。Windows 直接打开 `主机:~/目录` 时的 SSH 主目录查询仍无程序级超时。
- 自动监听地址在启动时枚举，网卡地址变化后需重启服务；客户端保存的服务端地址变化后需重新配对。
- `pair list/status` 仅读取本地记录；日志尚无自动轮转。VS Code 的最终连接结果以窗口提示为准。
