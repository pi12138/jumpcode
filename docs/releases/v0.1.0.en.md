# v0.1.0 release notes

[Project home](../../README.en.md) · [Usage](../usage.en.md) · [Development](../development.en.md) · [简体中文](v0.1.0.md)

The first stable release. Ask VS Code on a Windows desktop to open a remote project from a Linux terminal, or open local and SSH projects directly on Windows.

## Changes since v0.1.0-beta.1

- Fix `jc pair list` being rejected by a Windows platform check on Linux. Windows lists issued pairings; Linux shows the locally saved server address and certificate fingerprint.
- Platform errors identify the specific pairing command and whether to run it on the Windows server or Linux client.
- Unpaired machines show "No pairings" in `pair list/status`. Damaged or incomplete settings still report errors. Tokens and token hashes are not displayed.
- Reduce the default total HTTP request timeout for `jc client` and `jc pair join` from 30 seconds to 10 seconds. TCP connections and TLS handshakes each have a 3-second limit.
- Add `--timeout` to override the total timeout for one request, such as `jc c . --timeout 5s`. Zero and negative values are rejected, and a timed-out request preserves existing pairings.
- Add regression tests for full CLI commands, slow responses, and stalled TLS handshakes, and update the bilingual usage guide.

## Features

- Run `jc client .` on Linux to ask Windows VS Code to open the current folder through Remote-SSH.
- Open local folders, `host:/folder`, and `host:~/folder` directly on Windows.
- Manage credentials with `jc pair create/list/revoke/join/status`. Each token is bound to a fixed SSH host and can be revoked independently.
- TLS 1.3, certificate fingerprint pinning, and server-side token hash storage.
- Multiple IPv4 listeners, with `auto` selecting private IPv4 addresses on active interfaces by default.
- Windows background operation, status checks, stopping, and startup after user sign-in. Background logs record lifecycle and open requests while hiding project paths and tokens.
- Chinese and English interfaces, command aliases, and version information.

## Installation and upgrade

Artifacts include a Windows amd64 ZIP, Linux amd64 tar.gz, `release.json`, and `SHA256SUMS`. Archives include the executable, bilingual guides, and these notes. See the project home for installation instructions.

Existing pairing settings from the beta remain valid; pairing again is not required. On Windows, run `jc server stop` before replacing the executable and keep its original path so existing sign-in tasks continue to work. Run `jc server --daemon` after replacement to start immediately.

## Validation and known limitations

- The release workflow runs formatting checks, `go vet`, tests, and builds on Windows and Linux, with race detection on Linux. It also verifies archive checksums and the Linux CLI. Automated checks do not cover actual Windows desktop windows or user sign-in interaction.
- The server supports Windows and the client supports Linux. No public relay or IPv6 support is provided.
- Pairing configuration does not yet have a process lock. Run credential creation and revocation sequentially.
- Opening `host:~/folder` directly on Windows uses an SSH home-directory query without an application timeout. The request timeout changes do not affect that operation.
- Automatic listen addresses are discovered at startup. Restart after interface changes and pair again if the client's saved server address changes.
- `pair list/status` only reads local records and does not verify server availability or revocation. Revoke credentials on Windows.
- Logs are appended without automatic rotation. Check the VS Code window for the final connection result.
