# v0.2.0 发布说明

[项目首页](../../README.md) · [使用指南](../usage.md) · [开发指南](../development.md) · [English](v0.2.0.en.md)

正式功能版本。Windows 登录自启统一使用 `jc task` 管理，`auto` 监听可随网络变化自动调整。本版本替换了 v0.1.1 的任务管理命令，升级前请先清理旧任务。

## 相比 v0.1.1 的改进

- 新增 `jc task install/uninstall/start/stop/status`，支持短命令 `jc t`、`jc t st`。移除 `jc s startup` 和 `jc s start`。
- 使用 Windows 原生 Task Scheduler COM 接口管理当前用户的登录启动任务。任务直接运行同一个 `jc.exe server`，在自身进程中脱离控制台，无额外常驻启动器。标准输出、错误输出和 panic 记录到 `server.log`；启动瞬间仍可能短暂闪窗。
- `install` 只注册任务，`start` 最多等待 10 秒确认服务就绪，`stop` 通过本机认证控制接口正常停止；`uninstall` 先停止再删除任务，保留配对凭据、证书和日志。任务模式与手动后台模式使用各自的运行状态文件。
- `auto` 订阅 Windows IPv4 地址和接口变化通知，合并约 500 毫秒内的事件后增删监听。未变化的监听和已有连接保留，服务 PID 和证书指纹保持不变，前台、手动后台和计划任务三种模式均支持。
- 暂时没有可用地址时保持进程和本机控制接口运行，网络恢复后继续监听。枚举或绑定失败每 3 秒重试，重复错误合并记录，健康状态不持续轮询网卡。
- 手动后台启动保留原始 `auto` 配置。状态命令显示当前实际监听；没有监听时明确区分进程运行与服务就绪，仍可正常停止。
- 更新中英文安装、模式切换、升级、日志排查、架构和开发指南。

## 安装与升级

提供 Windows amd64 ZIP、Linux amd64 tar.gz、`release.json` 和 `SHA256SUMS`。压缩包包含程序、双语指南和此发布说明。安装及校验方法见[项目首页](../../README.md#安装)。

从 v0.1.1 或更早版本迁移登录启动任务时，**在替换程序前使用旧版 jc** 执行：

```powershell
jc s startup uninstall
```

这会停止旧任务启动的服务并移除任务，保留配对配置。将新版 `jc.exe` 放到固定安装目录，再执行：

```powershell
jc task install --listen auto
jc task start
jc task status
```

如果已替换程序，请按[旧版任务清理](../usage.md#旧版任务清理)结束并删除旧任务，再安装新版任务。已有当前 `jc task` 机制的测试版本，安装路径及监听配置不变时，只需 `jc task stop`、替换原路径程序、再 `jc task start`，无需重装任务。

手动后台模式先用 `jc s stop` 停止，替换程序后用 `jc s --listen auto -d` 启动；前台服务先按 `Ctrl+C`。不要删除用户配置目录，可继续使用已有配对凭据和证书。Linux 客户端替换 `jc` 即可。

## 验证范围与已知限制

- 本地已通过完整 Linux 测试及竞态检查、Linux/Windows `go vet`、双平台编译、Windows 测试交叉编译和文档链接检查。发布流程还会在原生 Windows/Linux 环境运行 CI，验证发布包校验和及 Linux 命令。
- 动态监听测试使用可控网络事件、地址快照和真实回环 HTTPS，覆盖地址增删、连接保留、断网恢复、绑定失败重试、状态更新和停止。测试不会修改机器网卡；真实 Wi-Fi/VPN 切换触发的 Windows 通知尚未在本地桌面环境验证。
- 自动验证不覆盖用户登录触发、完整计划任务管理与 VS Code 桌面交互；控制台测试使用隔离子进程。单个控制台程序启动后才脱离控制台，不能保证启动瞬间完全无闪窗。
- 服务端只支持 Windows，客户端只支持 Linux；暂无公网中转和 IPv6。客户端仍保存一个服务端地址，该地址变化后需要重新配对，自动监听不会向客户端发现或推送新地址。
- `jc task start` 超时不会撤销任务启动请求，进程可能仍在等待网络或重试。请通过状态和日志确认；`stop` 保留登录自启，`uninstall` 才移除任务。
- 明确指定的监听地址在启动时必须全部绑定成功；自动候选绑定失败会重试，其他监听继续服务。日志追加写入，尚无自动轮转。
- 配对配置尚无跨进程锁，请顺序执行创建和撤销操作。Windows 直接打开 `主机:~/目录` 时的 SSH 主目录查询仍无程序级超时。`pair list/status` 仅读取本地记录；VS Code 的最终连接结果以窗口提示为准。
