# v0.1.0-beta.1 release notes

[Project home](../../README.en.md) · [Usage](../usage.en.md) · [Development](../development.en.md) · [简体中文](v0.1.0-beta.1.md)

The first public beta. VS Code launch and sign-in behavior still need acceptance checks in your Windows desktop environment. Builds with `.snapshot` are development snapshots.

## Features

- Run `jc client .` on Linux to ask Windows VS Code to open the current project through Remote-SSH.
- Open local folders or `host:/folder` and `host:~/folder` directly from Windows.
- Manage credentials with `jc pair create/list/revoke/join/status`. Each token is bound to one SSH host and can be revoked independently.
- HTTPS uses TLS 1.3 and certificate fingerprint pinning; the server stores token hashes.
- Listen on multiple IPv4 addresses. The default `auto` selects private IPv4 addresses on active interfaces.
- Run in the Windows background, query status, stop the server, or start it after user sign-in.
- Both background modes log lifecycle and open requests, with project paths removed from logs.
- Chinese and English CLI messages, command aliases, and `jc --version` (`-v`).

## Artifacts

The Windows amd64 ZIP and Linux amd64 tar.gz include bilingual guides, these notes, and `release.json`. A separate `SHA256SUMS` covers both archives and the manifest.

Extract `jc.exe` or `jc` to a stable folder on `PATH`. If a sign-in task is installed, stop the server before replacing the executable and keep it at the installed path.

## Known limitations

- The server supports Windows and the client supports Linux. No public relay or IPv6 support is provided.
- Pairing configuration does not yet have a process lock. Run credential creation and revocation sequentially.
- Opening `host:~/folder` directly on Windows uses an SSH home-directory query without an application timeout.
- Automatic listen addresses are discovered at startup. Restart after interface changes and pair again if the saved server address changes.
- Logs are appended without automatic rotation. Check the VS Code window for the actual SSH connection result.
- The released binaries have not yet completed Windows desktop acceptance checks. Windows CI does not cover VS Code windows or actual user sign-in.
