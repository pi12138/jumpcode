# v0.2.1 发布说明

[项目首页](../../README.md) · [使用指南](../usage.md) · [开发指南](../development.md) · [English](v0.2.1.en.md)

正式修复版本，修复 Windows 计划任务脱离控制台后的标准流句柄生命周期问题，并让远程项目明确请求在新窗口打开。命令与配置兼容 v0.2.0，已有配对和证书可继续使用。

## 相比 v0.2.0 的改进

- Windows 计划任务脱离控制台前保留原始标准流对象，避免 GC 的 finalizer 再次关闭已由系统释放并被复用的句柄。误关复用句柄可能影响日志、socket 或 Go runtime IOCP，导致 `runtime: netpoll failed` 等异常退出；本次修复针对这一句柄生命周期缺陷。
- `jc client .`（`jc c .`）和 Windows 上的 `jc 主机:目录` 打开远程项目时，明确向 VS Code 请求新窗口，避免替换当前窗口中的其他项目。同一 SSH 主机的同一目录已打开时，由 VS Code 激活已有窗口；jc 不维护窗口列表。
- 补充中英文常用场景指南，覆盖局域网独立开发机、云服务器 SSH 反向转发、Tailscale、多主机配对及网络变化后的恢复步骤。

## 安装与升级

提供 Windows amd64 ZIP、Linux amd64 tar.gz、`release.json` 和 `SHA256SUMS`。压缩包包含程序、双语指南和此发布说明，安装与校验方法见[项目首页](../../README.md#安装)。

从 v0.2.0 升级时，无需重新配对，也无需重新安装计划任务。计划任务模式先停止服务，替换**任务实际指向的安装路径**下的 `jc.exe`，再启动并核对版本和状态：

```powershell
jc task stop
# 将新版 jc.exe 放回原安装路径
jc --version
jc task start
jc task status
```

任务保存的是程序绝对路径，仅替换终端 `PATH` 中的另一个副本不会更新任务。服务启动日志应显示 `v0.2.1`。

手动后台模式先执行 `jc server stop`，替换程序后用原监听配置重新启动；前台服务先按 `Ctrl+C`。Linux 客户端替换 `jc` 即可。保留用户配置目录中的凭据、证书和日志。从 v0.1.1 或更早版本迁移时，仍需先按[旧版任务清理](../usage.md#旧版任务清理)处理旧任务。

## 验证范围与已知限制

- 本地已通过完整 Linux 测试与竞态检查、Linux/Windows `go vet`、双平台构建和 Windows 测试交叉编译。发布流程对标签对应的源码运行原生 Windows/Linux CI，再生成并校验发布包。
- 新增 Windows 回归测试，在隔离子进程中模拟旧标准流句柄释放、复用并强制 GC，检查复用后的句柄及服务响应仍有效。URI 测试验证新窗口参数，并确认目录中的特殊字符不会改变窗口参数。
- 自动检查不覆盖完整 Windows 桌面交互、真实 VS Code 窗口表现或长时间稳定性。实际 SSH 连接结果仍以 VS Code 为准；计划任务启动瞬间仍可能短暂闪窗。
- 网络、凭据与配置方面的限制延续 v0.2.0：服务端仅支持 Windows，客户端仅支持 Linux；jc 监听和服务端地址仅支持明确的 IPv4。自动监听不会向客户端推送新地址，也不会更新配对绑定的 Linux SSH 目标。更多限制见[使用指南](../usage.md)。
